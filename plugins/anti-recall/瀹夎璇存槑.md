# 防撤回插件 · 安装说明

本插件能让 QQ Agent 在「群里 / 私聊」有人撤回消息时，用机器人身份把被撤回的原文（含图片、表情、`@`）重新发出来。

> ⚠️ **重要前提**：当前版本的核心代码没有在「消息 / 撤回」事件上暴露插件钩子，因此**只把插件文件放进去，它不会自动生效**——插件会被加载但不会触发，零副作用。要让它真正工作，必须按本文「步骤三」给核心 `src/app.js` 打一个很小的补丁（约 4 行，所有插件通用）。如果你用的是已经打过该补丁的版本（如作者后续发布的安装包），跳过步骤三即可。

---

## 一、文件清单

把插件目录 `plugins/anti-recall/` 整个拷过去即可，里面包含：

| 文件 | 作用 |
| --- | --- |
| `index.js` | 插件逻辑（缓存消息 + 撤回时重发） |
| `skill.json` | 插件清单与配置项（带 UI 表单） |
| `CORE-PATCH.md` | 核心补丁的完整代码（步骤三要用的） |
| `README.md` | 功能与限制说明 |
| `安装说明.md` | 本文档 |

## 二、两种安装方式（选其一）

### 方式 A：直接拷目录（最简单，但需先打补丁才有用）

适用于你**已经**在运行 QQ Agent（本项目 v0.4 及以上），只想加这个插件：

1. 拿到 `anti-recall` 文件夹（连同里面的全部文件）。
2. 把它放进 QQ Agent 程序的 **`plugins/`** 目录下。
   - 最终路径应为：`…/QQ Agent/plugins/anti-recall/index.js` 这样的结构。
   - 不要把 `index.js` 直接丢进 `plugins/`，必须是 **`plugins/anti-recall/` 子目录**。
3. 重启 QQ Agent。
4. 在「插件 / 技能」管理页找到 **「防撤回」**，确认它已启用（默认启用）。
5. **此时若未打步骤三的补丁，插件只是待命，不会自动重发**——请继续看步骤三。

### 方式 B：从源码打包（开发者）

如果你是自己拉源码跑 / 想重新构建安装包：

1. 把 `anti-recall` 文件夹复制到项目根的 `plugins/` 下。
2. 按步骤三给 `src/app.js` 打完补丁。
3. 正常 `npm run dist:win`（或对应平台脚本）重新打包即可。

## 三、核心补丁（让插件真正生效，必须做）

> 改动只涉及 **1 个核心文件** `src/app.js`，约 4 行新增，且补丁是**通用钩子**，不影响其它功能，可随时回滚。

### 3.1 打开 `src/app.js`，找到函数 `handleOneBotEvent`

（当前大约在文件第 1022 行，函数签名是 `async function handleOneBotEvent(event) {`）

### 3.2 把函数体替换为下面的内容

新增的行已标注 `↓↓↓`，其余保持不变：

```js
  async function handleOneBotEvent(event) {
    if (!event || typeof event !== 'object') return;
    if (event.post_type === 'message' || event.post_type === 'message_sent') {
      // 自己发的消息（message_sent / self_id 相同）不触发处理（发送时已自行记录）
      if (String(event.user_id ?? event.sender?.user_id ?? '') === onebot.selfId) return;
      if (event.message_type === 'group' && event.group_id != null) {
        const chatKey = `group:${String(event.group_id)}`;
        // ↓↓↓ 新增：把消息交给订阅了 onMessage 的插件（缓存原文供防撤回等使用） ↓↓↓
        await skillManager.runHook('onMessage', {
          event, chatKey, onebot, sender, store,
          sendSegments: (kind, id, segs) => sender.sendSegments(kind, id, segs),
          log
        });
        return ingestMessage('group', String(event.group_id), event);
      }
      if (event.message_type === 'private' && event.user_id != null) {
        const chatKey = `private:${String(event.user_id)}`;
        // ↓↓↓ 新增 ↓↓↓
        await skillManager.runHook('onMessage', {
          event, chatKey, onebot, sender, store,
          sendSegments: (kind, id, segs) => sender.sendSegments(kind, id, segs),
          log
        });
        return ingestMessage('private', String(event.user_id), event);
      }
      return;
    }
    if (event.post_type === 'notice' && event.notice_type === 'notify' && event.sub_type === 'poke') {
      return ingestPoke(event);
    }
    // 撤回事件：群撤回 group_recall / 好友撤回 friend_recall
    if (event.post_type === 'notice' && (event.notice_type === 'group_recall' || event.notice_type === 'friend_recall')) {
      const isGroup = event.notice_type === 'group_recall';
      const chatKey = isGroup ? `group:${String(event.group_id)}` : `private:${String(event.user_id)}`;
      // ↓↓↓ 新增：先让订阅了 onRecall 的插件（如防撤回）把原文重发出来 ↓↓↓
      await skillManager.runHook('onRecall', {
        event, chatKey, mid: event.message_id, onebot, sender, store,
        sendSegments: (kind, id, segs) => sender.sendSegments(kind, id, segs),
        log
      });
      return handleRecall(event);
    }
    // meta/心跳等事件忽略
  }
```

> 也可用 `plugins/anti-recall/CORE-PATCH.md` 里的同一份代码直接复制。

### 3.3 确认依赖变量可用

`skillManager` 已在 `src/app.js` 顶部导入（`import { skillManager } from './skills/manager.js'`），`onebot` / `sender` / `store` / `log` 都在 `app()` 作用域内，补丁可直接引用，无需额外 import。

`skillManager.runHook` 自带**错误隔离 + 超时保护**，单个插件抛错只记日志、不影响其它插件、不阻塞退出，所以放心直接 `await`。

## 四、验证安装是否成功

1. 重启 QQ Agent，进「插件 / 技能」页，确认 **「防撤回」** 状态为「已启用」。
2. 在群里发一条带「文字 + 图片」的消息，**自己把它撤回**。
   - 预期：机器人立刻把原文（含图片）重新发到群里，开头带 `【防撤回】` 前缀。
3. 如果图片重发失败，机器人会**自动回退为纯文本**提示「含图片/表情，已无法完整恢复」——这说明协议端已清掉图片缓存，属正常限制（不是插件 bug）。
4. 超过缓存时长（`缓存存活(分钟)`，默认 60 分钟）的撤回，插件会尝试 `get_msg` 回查；若协议端也清了，则静默放弃。

## 五、配置项（在插件管理页可调）

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 群消息防撤回 `groupEnabled` | 开 | 群里有人撤回时重发原文到群 |
| 私聊防撤回 `privateEnabled` | 开 | 私聊对方撤回时重发回去 |
| 显示撤回者 `showOperator` | 开 | 重发内容里注明执行撤回的 QQ 号 |
| 重发原文内容 `showContent` | 开 | 关掉后只提示「有人撤回了一条消息」，不重发具体文字/图片 |
| 重发图片/表情 `includeImages` | 开 | 关掉则图片段显示为 `[图片]` 占位（图片可能因协议端清缓存而失效） |
| 重发时 @ 撤回者 `atOperator` | 关 | 仅群消息有效，开启后 `@` 执行撤回的人 |
| 前缀文案 `prefix` | `【防撤回】` | 重发消息开头文字，便于一眼识别 |
| 缓存存活(分钟) `cacheTTLMin` | 60 | 每条收到的消息在内存保留多久用于还原；超时只能靠 `get_msg` 回查 |
| 重发冷却(秒) `cooldownSec` | 1 | 同一会话两次重发的最小间隔，防刷屏 |

## 六、常见问题

**Q1：插件放进去重启了，但撤回时没反应？**
A：大概率是没打「步骤三」的核心补丁。检查 `src/app.js` 的 `handleOneBotEvent` 里是否有 `runHook('onMessage'` 和 `runHook('onRecall'` 这两处调用；没有的话插件只是待命。

**Q2：撤回的图片重发不出来 / 显示「已无法完整恢复」？**
A：QQ 协议端（NapCat / Lagrange / SnowLuma）在消息撤回后会清理本地图片缓存，这是协议层限制，插件无法绕过。文案里的提示属正常行为。若希望尽量保留图片，把「缓存存活(分钟)」调大一些（在撤回发生前缓存命中即可重发原图）。

**Q3：会不会很吃性能 / 拖慢收消息？**
A：不会。`onMessage` 只做一次内存 Map 写入（<1ms），`onRecall` 只做缓存查找 + 一次发消息。`runHook` 没有订阅者时近乎零成本。

**Q4：想卸载怎么办？**
A：删掉 `plugins/anti-recall/` 文件夹并重启即可；若打了核心补丁，删掉 `src/app.js` 里标注 `↓↓↓` 的 4 行即可回滚（也可保留，不影响其它功能）。

**Q5：这个插件会改动我其它的文件吗？**
A：插件本身**完全自包含**，只新增 `plugins/anti-recall/` 目录。唯一需要你手动改的是「步骤三」的核心补丁（约 4 行，且是通用钩子，其它插件也能用），不在本插件目录内。

## 七、适用版本

- QQ Agent v0.4 及以上的插件体系（`plugins/` 目录 + `skillManager.runHook`）。
- 协议端需为任一标准 OneBot v11 实现（NapCat / Lagrange / go-cqhttp / SnowLuma 等）。

# 刷视频 / 刷帖子 / 上网 —— 她自己的内容流 + 她自己的浏览器

给她两样属于自己的东西：

1. **一条自己的内容流** —— 到点自己刷一会儿，看完真的记下"看到了什么"
2. **一个自己的浏览器** —— 没人给网址时也真能上网：打开网页、读正文、截图看画面、带上她自己的账号登录态

攒到想说的时候，用她自己的口吻、分成一两条短消息主动发出去。

装好即用（默认开）。控制台页签「**刷视频 / 上网**」（在「会话」右边）里可以逐项调，
改完点保存立刻生效（热重载，不用重启应用）。

---

## 一、它做的四件事

| 环节 | 具体行为 |
|---|---|
| **源** | `bilibili`（B站热门视频）· `hot`（网上热帖）· `qzone`（好友 QQ 空间动态，只读）；上网时的来源是 `surfSites` 里她自己"爱去的地方" |
| **看** | 视频真的看：先封面；能下到（≤ `frameMaxMB`）就**下载 → 抽帧 → 画面交给视觉模型**。帖子读标题+正文。网页用她的浏览器打开 → 读正文 → **截一张图**给她看 |
| **上网** | 有 `surfChance` 概率的一轮不刷视频、改成上网：从 `surfSites` 随机挑一个真打开（也可以由用户丢网址、或她聊天时自己判断「我看看这个」）。只读页面：不点按钮、不填表、不提交 |
| **真播** | `biliPlaySeconds > 0` 时，B站 视频会先用她的浏览器打开视频页**真播这么多秒**（默认 15），再去抽帧。这是"让观看进 B站 观看历史"的开关 —— 见下面第四节 |
| **说** | 攒一条"有话想说"的，按概率开口：用你的人设口吻写 1~2 条短消息，中间随机停 1.2~4.6 秒（像真的在打字），走 OneBot 发出去 |
| **甩链接** | 看每条内容时她自己判一句「这条值不值得把链接也甩给他」；判定值得（`sendLinks` + 概率）时，**单独补一条消息把干净链接发出去**（像人复制粘贴）。也可以随时手动要：页签每条记录上有「把这条链接发给我」。见第五节 |

### ⚠️ 「她说看了，为什么 B站 观看历史里没有」

这是**设计使然**，不是她撒谎：

- 看视频走的是 **B站 接口拿 playurl → CDN 直下 mp4 → ffmpeg 抽帧 → 删文件**
  （`downloadWithCap` + `grabFrames`）。**浏览器从来没打开过视频页、播放器没启动**，
  B站 服务器收不到任何播放行为，所以它的「观看历史」是空的。
  好处：不会往你账号的历史里灌东西；代价：外部看不到"她看过"。
- 视频超 `frameMaxMB`（默认 8MB）时连下载都不下，**只看了封面**。日志会写
  「超过 8MB，不下，改看封面」，记录里也会写「只看到封面（视频太大没下下来）」。
- **想看"她看过的"出现在 B站 历史里** → 把 `biliPlaySeconds` 设成 15~30
  （页签 → 刷内容 → 「B站视频在浏览器里真播几秒」）。之后每条 B站 视频会先在
  她的浏览器里真播一会儿：`playVideo()` 打开视频页 → `video.play()` → 盯 `currentTime`
  真的在涨 → 关窗（触发 pagehide，播放器借 sendBeacon 补报进度）→ 服务器才记账。
  代价：每条视频多十几秒 + 走一遍播放流量。

**验证过的事实**（用她自己的账号、在她自己的登录态里读 `bilibili.com/account/history`）：

| 动作 | 观看历史页面 |
|---|---|
| 她"刷"过 3 条（只抽帧/封面） | 写的是「**还没有观看记录**」 |
| 在浏览器里真播 20 秒某条视频 | 该条出现在历史里：`今天 19:52 00:19/03:27` |
| 开着真播刷一轮（2 条，含 1 条 B站） | 历史里能看到 **5 个视频**，含刚那条 `00:28/05:27` |

如果她嘴上说"看了"但你怀疑，页签里点「**查 B站 观看历史（核实她真看了没）**」
（命令 `bili_history`）—— 它会用她的登录态打开历史页、把 BV 号和进度读回来说给你听。

### ⚠️ 第二个坑：「刚让她刷了，B站 历史还是不动」

开了真播之后仍然可能一轮下来历史不动，原因是**这一轮压根没刷到 B站 的视频**。
实测日志长这样：

```
20:04:45 [刷视频] 刷了一轮：看了 2 条（hot）
20:09:50 [刷视频] 刷了一轮：看了 2 条（hot）
```

两轮全是 `hot`（网上热帖）—— 热帖没有播放器，真播那一步根本不触发。为什么会这样：
**B站 热门只拉第一页（20 条）**，当天刷掉二十几条之后，这个源就被去重表吃空了；
而 `fresh.length === 0` 时又**直接 return**（"去重后没有新内容"），于是每轮只剩热帖。

修的三处：

1. `biliPages`（默认 3）→ 翻 3 页 = **60 条候选**。⚠️ 实现时踩了个小坑：不能写
   `ps = limit / pages`（那等于"3 页共 20 条"，实测一轮只剩 1 条候选），每页固定 20 条。
2. `reseenHours`（默认 8）→ **全新内容刷完之后**，把超过 8 小时的旧内容重新放回候选。
   不再"一天就刷这么二十条然后彻底停摆"。
3. **结果里说清楚为什么**：`看了 2 条（bilibili）；hot 这轮没有新内容（都刷过了）`、
   `没有全新内容，挑的是 8 小时前刷过的`。以前只写"看了 2 条（hot）"，用户完全看不出
   是去重把 B站 那条路堵了。
4. 顺带：热帖里如果带的是 B站 视频链接（`bilibili.com/video/BV…`），也照样走真播
   （判据从 `source === 'bilibili'` 改成 `source === 'bilibili' || isBiliVideoUrl(url)`）。

修完实测：一轮 `看了 2 条（bilibili）`、两条各真播 21 秒 → B站 历史 **6 → 7 → 10 条**，
新增条目带进度 `今天 20:18　00:23/36:50　"这才是许愿池真正的意义…"`。

### ⚠️ 两张卡没挂到 DOM 上（v1.7.1 修掉的真事故）

"主人账号设置根本找不到"不是没做，是**做完了没挂上去**，而且是三个错叠在一起：

1. `c7`（评论区那张卡）**从头到尾没有 `main.appendChild(c7.node)`** —— 建出来、填满字段，然后扔了；
2. 后面又写了一个 `var c6 = card('维护')`，**把"主人账号 / QQ 总结"那张 c6 覆盖了**，
   于是 `main.appendChild(c6.node)` 挂上去的是"维护"卡 —— 主人账号那张永远进不了页面；
3. 修的时候把 `appendChild(c6.node)` 放在 `var c6` **声明之前**执行 —— `var` 提升成 `undefined`，
   直接 `TypeError: Cannot read properties of undefined (reading 'node')`，整段渲染中断
   （控件从 42 掉到 26）。

**怎么发现的**：不相信"应该没事"，而是**打开控制台页面自己数控件** ——
内部浏览器里点开页签，`querySelectorAll('[data-key]')` 列出来，发现
`ownerQQ` / `biliAtUid` / `biliComment*` / `postEnabled` **一个都不在**；
再挂一个 `window.addEventListener('unhandledrejection')` 把渲染脚本重跑一遍，抓到
`TypeError ... at renderMain (ui.js:586:25)`，定位到就是那句 `appendChild(c6.node)`。

**现在的样子**：第一张卡就是「**👤 主人账号（识别我 / 要 @ 的人）**」——
主人 QQ、我的 B站 UID（旁边显示查到的昵称）、三个"认一次"按钮；
c6（QQ 总结 + @你）和 c7（评论区总结 + @我）都真挂上了。诊断命令 `ui_check` / `ui_eval`
以后随时能复查"页面到底渲染出了什么"。

## 二、控制台页签（在「会话」右边，直接点进去）

宿主没有"插件自己加路由/页面"的扩展点，所以走的是**宿主已有的两条既有机制**（和 `her-inner` 同一套）：

| 部分 | 文件 | 说明 |
|---|---|---|
| 数据 | `<app>/ui/feed-scroller/state.json` | 插件写的快照（状态、设置当前值、最近记录、账号**条数**），静态路由直接服务 `<app>/ui/` |
| 页面 | `<app>/ui/feed-scroller/ui.js` | 从插件目录复制过去的页面脚本 |
| 注入 | `<app>/ui/index.html` | 三处幂等插入：`data-tab="sessions"` 后面加按钮、`<!-- 存档视图 -->` 前加 `<section id="view-feed-scroller">`、`</body>` 前加脚本 |

- 备份：`<app>/ui/index.html.feed-scroller.bak` 与 `<app>/data/feed-scroller/index.html.original`
- **自愈**：宿主更新会整体替换 `ui/`，所以插件每 5 分钟确认一次页签还在不在（很便宜）
- **关掉**：设置里 `uiExtension = false` → 不再写 `ui/` 任何文件（页签要自己删）
- 页面只读快照：**任何 cookie 值都不进浏览器**（只显示"几个站点、各多少条"）

### 点按钮怎么"立刻干活"

页面把命令写进设置里的 `cmd` 字段（走宿主的 `POST /api/skills/<id>`，唯一认的写入路径），
插件每 **5 秒**取走执行、清空（`updateConfig({skills:{'feed-scroller':{cmd:null}}})`）、把结果写回快照。

| action | 干什么 |
|---|---|
| `scroll` / `surf` | 立刻刷一轮 / 上网逛一圈（不看静默时段和每日上限，手动就是要立刻） |
| `browse` | 用她的浏览器打开指定网址 → 读正文 + 截图 → 让她说一句看到什么（`url`；给视频页再传 `playSeconds` 就先真播一会儿） |
| `play_video` | 只做"真播"：打开视频页播 `seconds` 秒（默认 `biliPlaySeconds`），完事关窗补报进度 → 该条会进那个站的观看历史 |
| `bili_history` | 用她的登录态读 B站 观看历史页，回报 BV 号与进度（核实"她到底看没看"） |
| `test_browser` | 只测浏览器通不通（`url`），不让她说话 |
| `speak` | 立刻试着挑一句发出去（仍然过冷却/每日上限，日志写原因） |
| `open_login` / `open_account` | 弹一个**能操作的**登录窗口，你把账号登一次（`timeoutMs` 到点自动结算并关窗） |
| `account_status` | 每个站现在浏览器里有多少条 cookie（验证登录态在不在） |
| `clear_cookies` | 清某个站（或全部）的 cookie（`host`/`url` 都可以） |
| `forget_account` | 从账号簿删掉 + 顺手清 cookie |
| `clear_history` | 清空观看/上网记录与去重表 |
| `refresh` | 立刻重写快照 |

> 防误执行：命令带 `id` 和 `at`，执行过的 `id` 不重复执行；`at` 超过 **2 分钟**的旧命令直接丢弃
> （避免"应用一启动就把隔夜命令当新命令跑一遍"）。

## 三、她的账号（登录态给内部浏览器用）

`<data>/feed-scroller/accounts.json` —— 只存**她自己要用**的站点：

```jsonc
{ "sites": [ { "host": "bilibili.com", "name": "B站", "cookies": "SESSDATA=…; bili_jct=…",
               "source": "paste", "updatedAt": 1792408500000 } ], "importedHash": "…" }
```

两条来路，任选：

1. **粘贴**（控制台页签里）：每行 `域名 名称 Cookie`，也接受 JSON 数组。写完点保存 →
   插件 5 秒内导入账号簿。这个字段是 `secret`：**保存后不回显**（读出来是 `******`），
   留空 = 不修改（所以"清空"要用 `POST /api/config` 写空串，或干脆在页面里删掉站点）。
2. **打开登录窗口（推荐）**：弹一个真窗口，你亲手扫码/输密码登一次；关掉窗口，
   登录态就留在**她的浏览器分区** `persist:feed-scroller` 里，跨重启保留。
   账号簿里只记一笔"登过"（`source: "login"`），cookie 本体在 Chromium 的 jar 里。

访问某个站时：先注入该站的 cookie → 再重新加载一次 → 所以**第一屏就是登录态**。

## 四、"刷到有意思的就把链接发给我"

两条路，都是**发一条单独的链接消息**（不塞在闲聊正文里，像人切到剪贴板再粘过来）：

1. **她自己判断** —— 看内容那一趟（`WATCH_SYSTEM`）除了 `saw` / `say`，还要她答一句
   `share` + `why`：「值不值得把链接也甩给他」。判据写死在提示里：
   有意思 / 好笑 / 长见识 / 他八成会想看 → `true`；纯带货、标题党、卖课的、没看懂 → `false`；
   并明确"十条里三到五条" —— 不写死模型会条条都说值得。
2. **你手动要** —— 页签第一张卡「把最后刷到的那条链接发给我」，或记录清单里每条后面的
   「把这条链接发给我」；聊天里直接说「刚才那个视频发给我」也行（走 `feed_share` 工具）。

| 设置 | 默认 | 作用 |
|---|---|---|
| `sendLinks` | 开 | 总开关。关掉就只有话、没有链接 |
| `linkChanceShare` | 0.8 | 她判定"值得"→ 真发的概率（留点念想，不然每条都甩链接太机械） |
| `linkChance` | 0.15 | 她判定"一般"→ 顺手也发的概率（设 0 = 只有判定值得才发） |
| `linkLeadIn` | 开 | 约 35% 的链接前面带一句「你看看这个」这类引子；关掉就只发干链接 |

**链接会去尾巴**：`cleanUrl()` 把 `spm_id_from` / `vd_source` / `share_source` / `utm_*` 这些
参数删掉、B站 统一压成 `https://www.bilibili.com/video/BVxxxx`（`?` 后面那一长串一律不留）。

**两个"手动优先"的让路规则**（实测踩出来的）：`speakCooldownMin`（距上次主动不到 N 分钟）
和 `replyGuardMinutes`（对方刚说过话不另起话头）这两条礼貌/节流规则，
在**用户自己点按钮**（`force`）时让路 —— 手动点「现在就挑一句发出去」就是明确要现在发，
不该被 90 分钟节流拦掉（实测连点两次都被拦，功能等于废的）。
每天的 `dailySpeakCap` 和发送白名单照旧生效（那是防乱发的底线）。

实测（她自己的账号 + 真 QQ 私聊）：

```
20:39:19 把链接也发了（private:…）：https://www.bilibili.com/video/BV13bnE6ZEmP      ← 手动「把最后刷到的那条链接发给我」
20:44:05 这条她觉得值得你也看看（创意形式有意思，熊出没粉丝会想看）：熊出没最巅峰的一个系列，四季篇 → https://www.bilibili.com/video/BV1WXJq6cE7Y
20:44:57 她主动说了（private:…，1 条）：「有人把熊出没四季篇拍成真人编剧开会的短剧，白板上还写春日对对碰夏日连连看，挺有梗的」
20:44:57 把链接也发了（private:…）：这个你八成爱看　https://www.bilibili.com/video/BV1WXJq6cE7Y
```

## 四点五、"一条有意思的视频只做一件事" + 表情包（v1.8）

**问题**：一条有意思的视频，之前会同时触发三件事 —— 把链接发给你、在 QQ 里发总结+@你、
去视频评论区总结+@我。结果你一次收到三条通知，像刷屏。

**现在**：`shareOneAction = true`（默认）→ 同一条视频**只做一件**，三选一：

| 动作 | 做什么 | 谁负责 |
|---|---|---|
| `link` | 把干净链接单独发给你（像人复制粘贴） | `maybeSendLink` |
| `qq` | 在 QQ 里发「总结卡 + @你」（群里带 at 段） | `maybePostVideo` |
| `comment` | 去那条视频的**评论区**发总结 + @我 | `maybeCommentVideo` |

怎么挑：`shareActionPref` 默认 `随机`（在开着的几件里随机挑一件）；
也可以钉死成 `链接` / `总结` / `评论区` 只做那一件（其它两个开关关掉也行）。
**手动点按钮/工具调用（force）不受限制** —— 你明确要哪件就做哪件。

**"只做一件"怎么保证不重复**：一份对账表 `state.actioned[<干净链接>] = {action, at}`。
三个动作各自在开头问一句 `actionedBefore(item)`：做过别的事就退出并说明原因
（`这条已经做过「在 QQ 里发总结 + @你」了，一条只做一件事`），做完就 `recordAction` 记账。
一条都没成功时会**自动换成另一件**（优先级失败才切换），全失败才 warn。
对账表只留最近 300 条。

**表情包**（`emojiEnabled` 总开关，`emojiWithAt` = "@ 的时候配一个"）：

- **QQ 侧**：`emojiImage` 填图片路径/URL → 走 OneBot 的 **image 段**发真表情包；
  留空就用 **face 段**（`emojiFaces` 里随机挑一个 id，默认 `178,182,21,76,14`）——
  不用上传、一定发得出去。日志会写 `发了「视频总结 + 表情 182」到 private:…`。
  ⚠️ 带了表情就**必须走 OneBot 分段那条路**（核心发送能力只吃纯文本），
  所以 `sendCard` 的"先走哪条路"判断里，`mention || faceId || emojiImage` 都算"要走分段"。
- **B站 评论区**：用 B站 **官方表情 token**（`emojiBili`，默认 `[doge],[笑],[打call],[惊喜],[给心心],[星星眼]`），
  评论末尾追加一个，渲染出来就是表情图。**表情 token 不算进短评字数上限**
  （它渲成图，不算"话多"），实测：`@壹条小华仔 话题性强，容易引人讨论 [给心心]`。

## 五、在视频的评论区发总结并 @你（v1.5）

她要的不只是"发条消息给你"——**是在那条视频的评论区留一条总结、并 @你**。做法：

- 用她那套登录态（= 你那个 B站 账号）在视频页里 `fetch api.bilibili.com/x/v2/reply/add`；
- 拿 aid（页面 `__INITIAL_STATE__.aid` → 兜底 view 接口）+ `bili_jct`（CSRF，从 cookie 里取）；
- @ 的对象按 **B站 UID** 认昵称（`biliAtUid`，页面填你的 UID，如 `477537983` → 昵称「壹条小华仔」）：
  B站 的 @ 是**按昵称解析**的，所以评论里写 `@昵称`，光是 UID 没用；
- 发完 **按 rpid 反查确认**（`reply/reply?root=<rpid>`，重试 4 次×2.5s）——
  列表接口是按热度/分页给的，新评论常常翻不到，别拿它当"没发出去"。

日志长这样（实测）：

```
在她觉得有趣的视频下面评论了（BV1wanJ61EbW，rpid 317573716529｜服务端已确认这条在｜state=17）：@壹条小华仔 看完了：……
```

工具与命令：`feed_comment`（对话里说"去评论区 @我 一下"就用它）、页签按钮
「去最新那条视频的评论区发总结 + @我」、诊断命令 `bili_probe` / `bili_whoami` /
`bili_at_probe` / `comment_check` / `comment_by_rpid`。

**所以"到底公开了没有"只有一个判据：`state`**（用 rpid 反查那条评论，`state=0` 才是公开）。
实测（同一账号、同一天）：

| 评论正文（字数） | state | 后果 |
|---|---|---|
| `@壹条小华仔 看完了：<长段画面描述> 我觉得<感想>`（100+ 字） | **17** | 压审核：只有发布者自己看得见，公开列表翻不到，**@ 的通知也不会发** |
| `@壹条小华仔 三角洲新出的干员野火，图上妹子直接踹墙突入，看着挺猛，11月5号上线。`（40 字） | **17** | 同上：带细节/日期的句子照样被压 |
| `@壹条小华仔 熊出没老粉看了会有共鸣`（20 字） | **0** | 直接公开 ✅ |
| `@壹条小华仔 熊出没企划设定，粉丝会想看`（20 字） | **0** | 直接公开 ✅ |

**规律：越短越像人越安全**（20 字左右的一句人话稳过；40 字带细节/日期就进审核）。
所以 `biliCommentShort = true` + `biliCommentShortChars = 24`（短评字数上限）是默认档：
它从 `why`/`say` 里**挑最短的那句**，去掉"我觉得/看完了"这种 AI 味前缀。
想要长总结就关掉短评模式，代价就是大概率被压审。

结论：**长文 + @ + 大量标点引号** 会被 B站 当可疑内容压审 —— 这是站方的闸门，不是插件的问题。
所以默认开了 **`biliCommentShort = true`（短评模式）**：只写一句像人随手留的话。
想回到长总结就把这个开关关掉，但要接受被压审的可能（那样你自己在评论区也看不到，只有她看得见）。

**过审监视**：发出去的评论按 BV 记进 `state.commented[bv] = {rpid, text, state, checkedAt}`；
每轮刷流水时顺手查最多 2 条（60s 内不重复查），过审就写一行
`✅ 评论区那条已过审公开（…）—— @ 的通知这时候才会到对方那里`；
页面上有按钮「看我发出去的评论过审了吗」（命令 `comment_states`），
回填用 `comment_track {bvid, rpid}`。

**控制旋钮**：`biliComment`（总开关）、`biliCommentShort`（短评模式，默认开）、
`biliCommentMention`、`biliCommentChance`（默认 0.6）、`dailyCommentCap`（默认 3）、
`biliAtUid`、`biliCommentAt`（手填昵称兜底）、`biliCommentChars`、`biliCommentText`（模板）。
同一条视频只评论一次（`state.commented[bvid]`）。

诊断命令：`bili_probe`、`bili_whoami`、`bili_at_probe`、`comment_check`、
`comment_by_rpid`（看 state）、`comment_locate`（翻公开列表找）、`comment_recent`（看最新评论的 state 分布）、`comment_states`、`comment_track`。

## 五点四、@ 到底有没有点到人（v1.9 实测）

**机制通了，通知被审核挡住。**

- 通的部分：B站 评论对象里明确记着 `at_name_to_mid={"壹条小华仔":477537983}` ——
  B站 自己认下"这条评论 @ 的是 UID 477537983"，不靠猜名字。为此新增 `biliAtBindUid`（默认开）：
  发评论时把「昵称 → UID」映射（`at_name_to_mid` / `at_name_to_mid_str`）一起 POST 上去。
- 挡的部分：`state=17`（压审，只有她自己看得见）不会推 @ 通知。

### 压审规律（同一个号、同一天、连着发 6 条）

| 评论 | state |
|---|---|
| `@壹条小华仔 熊出没老粉看了会有共鸣`（20 字、无表情，当天最早） | **0 公开** ✅ |
| `@壹条小华仔 熊出没企划设定，粉丝会想看`（20 字、无表情） | **0 公开** ✅ |
| `@壹条小华仔 三角洲新出的干员野火…11月5号上线。`（40 字） | 17 压审 |
| `@壹条小华仔 话题性强，容易引人讨论 [给心心]` | 17 压审 |
| `@壹条小华仔 讲扫地机避坑，买家会想看 [打call]` | 17 压审 |
| `@壹条小华仔 做法反常识又实用`（无表情、20 字内） | 17 压审 |

→ **不是表情、也不是字数**（最后一条什么都没带，照样 17），是**连着发**把号顶进审核。

### 因此的三道闸

| 设置 | 现在 | 作用 |
|---|---|---|
| `commentMinGapMinutes` | 90 | 两条评论至少隔这么久，不够就跳过并写明原因 |
| `dailyCommentCap` | 2 | 一天最多几条 |
| `biliCommentChance` | 0.35 | 每条视频去评论的概率 |
| `emojiBiliUse` | false | B站 评论默认不带表情 token |

### 顺带修掉的真 bug

有一条评论正文变成 `@壹条小华仔 {"saw":"一个19分钟的时政视频，标题是…` ——
模型把 impression 当**半截 JSON 字符串**塞进 `why`，`JSON.parse` 解不开就原样发了出去。
现在 `asText()` 对坏 JSON 用正则硬抠 `"saw"|"why"|"say"` 那句；抠不出来返回空，
所有出口再过 `isJunkText()`（含 `{}`、`"x":`、`\"` 一律不发）。那条评论用 `comment_delete`
（B站 `x/v2/reply/del`）删掉了。

## 六、内部浏览器（`lib/browser.js`）

- 形态：Electron 主进程里一个真 `BrowserWindow`，独立持久分区 **`persist:feed-scroller`**
  （和 `media-download` 的抖音桥完全分开，互不打扰它的 cookie jar）
- 读页面：`executeJavaScript` 取 `title` / 正文 `innerText` / `description` / `finalUrl`，
  再 `capturePage()` 拿一张 JPEG 截图（≤900px 宽、质量 72）当视觉输入
- **安全面**：只放行 `http` / `https`（`file:` / `data:` / `javascript:` 全拒）；
  `nodeIntegration:false` / `contextIsolation:true` / `sandbox:true`；只读页面，不点不填不提交
- 默认**后台静默**（`browserVisible=false`）；开了就看得见那个窗口在翻页
- 打不开时（超时 / 证书 / 被墙）自动**退回朴素抓取**再试一次，这一轮不白跑
- 模块在非主进程里（比如自检脚本用普通 node 跑）会自动判定"不可用"，退化为朴素抓取

### 默认"爱去的地方"是实测能打开的

```
https://top.baidu.com/board?tab=realtime        百度热搜
https://www.bilibili.com/ranking                B站排行榜
https://tieba.baidu.com/hottopic/browse/topicList 贴吧热议
https://news.qq.com/                            腾讯新闻首页
```

> 踩过的坑：把维基百科随机条目放默认清单 → 国内网络 `ERR_CONNECTION_TIMED_OUT`，
> 每轮上网都白跑。另外知乎 403、微博要登录。换自己的站点前先确认这台机器打得开。

## 七、硬闸门（都在代码里，不靠提示词）

- **每日**：看 `dailyWatchCap` 条、上网 `dailySurfCap` 次、主动说 `dailySpeakCap` 次，到量就停，零点重置
- **静默时段**：`quietRange`（默认 02:00-08:00，**代码级默认**，设置留空也不放开）内不刷、不上网、不发
- **去重**：同一视频 / 同一条动态 / 同一个网页只刷一次（`seen` 表，`keepDays` 天过期）
- **节奏**：两次主动之间至少 `speakCooldownMin`；对方刚说过话 `replyGuardMinutes` 内不插嘴
- **发送白名单**：主动发送走 OneBot HTTP，绕过了核心发送闸门，所以这里自己判一次
  `config.allow / config.deny`（不在白名单或命中屏蔽 → 直接不发，日志写原因）
- **噪声过滤**：空间动态里的广告直接丢；**自己发的说说**跳过（刷自己的帖子没意义）
- **单轮互斥**：一轮没跑完不会再起一轮
- **手动 / 工具路径的豁免范围**（写清楚，免得以为是漏了闸门）：
  - 豁免**静默时段** —— 你手动点的"立刻刷一轮"，当然要立刻执行
  - 刷内容的**每日上限仍然算数**：到量会回你"今天已经刷了 N 条，到量了"
  - 用户**点名要看某个页面**（`__browse` / `browse` 命令）时，连每日上限和去重一起豁免
    —— 他明确要看，重复看同一页也是合理的

## 九、上下文注入

`injectRecent` 打开时，最近 `injectMaxItems` 条（`injectMaxHours` 小时内，**含上网看到的页面**）
会作为一小段【你最近刷到的】贴到每轮消息尾巴上 —— 所以她聊天时能自然冒一句"我刚刷到一个…"。
注入的那段带防线：只在话题接得上时提，不许报菜名式罗列。

## 十、省钱旋钮

| 想省 | 怎么调 |
|---|---|
| 不花视觉钱 | `tryFrames` 关掉（只看封面 + 标题简介）；网页那边的 `browserShot` 关掉 |
| 不上网 | `surfEnabled` 关掉，或 `surfChance` 调 0（仍可被用户叫去上网） |
| 整体减半 | `intervalRange` 拉长（如 `120-240`）、`watchMin/Max` 降到 1、`dailySurfCap` 降 |
| 少说话 | `speakEnabled` 关掉，或 `speakChance` 降到 0.1 |
| 每轮更省 | `maxFrames` 降到 1、`injectMaxItems` 降到 1、`browserMaxChars` 降到 2000 |

每轮大致花费：**每条 = 1 次视觉调用**，每轮最多再 **1 次**写话调用。
没抽到帧、没内容可看、不在时段内时不会调模型。

## 十一、存档与排障

| 想看什么 | 在哪 |
|---|---|
| 观看/上网记录、去重表、每日计数、攒着想说的 | `<data>/feed-scroller/state.json` |
| 账号簿（站点） | `<data>/feed-scroller/accounts.json` |
| 页面快照 | `<app>/ui/feed-scroller/state.json`（控制台页签读的就是它） |
| 视频缓存 | `<data>/feed-scroller/video-cache/`（抽帧后 mp4 立即删） |
| 日志 | 日志页搜「**刷视频**」：每轮刷了几条、抽到几帧、开的哪个网页、读了多少字、她说了没有 |

### 踩过的坑（都已在代码里防住）

1. **抽帧返回的是 data URL，不是文件路径** —— 早期版本对 `data:image/jpeg;base64,…` 做 `statSync`
   → `ENAMETOOLONG`。现在两种都接，并且每条静默返回都记一行日志。
2. **静默时段设置留空 ≠ 不限制** —— 早期版本会退化成"全天可刷"。现在代码级默认 `02:00-08:00`。
3. **一轮被单一来源占满** —— 现在先去重再把各源交错（`看了 3 条（bilibili+hot）`）。
4. **热重载会留下"旧实例的旧存档"** —— 宿主重载走 `import(entry + '?t=…')`，每次都是**新模块实例**，
   旧实例的内存 cache 还活着；真实故障：旧实例拿着 18:59 的 cache 写盘，把新实例 19:12 刷到的内容整个覆盖
   （表现为"日志里明明刷了、控制台里却没有"）。现在 `loadState()` **比对文件 mtime**，文件被别处改新了就重读。
5. **更狠的一层：热重载会留下"旧实例的定时器"** —— 加载器只 `deactivate()` 它记着的那个实例，
   实测出现过 **两个实例各跑一套**（4 个定时器 ×2 = 一次启动清掉 8 个残留）。
   现在定时器统一登记在 `globalThis.__feedScrollerTimers`，`startLoop()` 先清干净再登记自己的；
   另外 `saveState()` 会在写盘前**把磁盘上"我没见过"的记录并进来**（items 按 `id@时间` 去重、
   `seen` 取并集、每日计数取大值），`buildSnapshot()` 一律**从磁盘读**。
   三层一起上之后，"谁写都不会丢东西、页面显示的永远是磁盘真身"。
6. **`import('./lib/browser.js')` 会拿到旧模块** —— 插件本体每次热重载都是新 URL，
   但子模块的 specifier 没变，Node 直接还旧实例 → 新加的函数（`playVideo` / `runInPage`）
   在运行中的应用里永远是 `undefined`（实测报 `lib.playVideo is not a function`）。
   现在按**文件 mtime** 做缓存戳（`?v=<mtime>`）：文件没改就复用同一实例（保住那个隐藏窗口这个单例），
   改了才换新实例，换之前先关掉旧实例的窗口。
7. **B站 是 SPA，`loadURL` 会 `ERR_ABORTED`** —— 页面自己又跳了一次，外层以为失败。
   现在 `alreadyThere()` 判定"人已经在同一个站上了"就继续（否则"视频页播不了"是个假故障）。
8. **B站 的历史接口在浏览器里裸 `fetch` 会被判异常**（返回 412 的 HTML，报
   `Unexpected token '<'`）。所以 `bili_history` 改成**读历史页面自己的 DOM**（BV 号 + 正文），
   带着她的登录态走正常页面渲染，最准。
9. **每日计数会莫名变小** —— 实测"今天看了 54 条"掉成 27 条、记录条数也从 40 掉到 28。
   写盘是"读-改-写"，某个残留实例/边界状态带着更小的计数写回去就把它拉低了。
   现在规则是**只升不降**：磁盘上那份只要是"今天"的，计数一律取两边的大值（不看我这句是哪天的），
   记录 items 永远取并集；每次写盘后刷新一份 `state.json.bak`，主档万一读不出来就用备份当底本
   （会 warn 出来，是"首次创建"也会说一声，不静默覆盖）。修完连刷多轮：计数 37→40→43、
   记录 38→41→45，只涨不跌。
10. **`runInPage` 自己就包了一层 `{ ok, data }`** —— 脚本里再 `return { ok: true, data: out }`
    就是**两层**，`r.data.nick` 永远是空（实测：昵称明明拿到了却读成空，白查半天）。
    脚本里直接 `return out`，外面取 `r.data.xxx`。
11. **模型偶尔把整段 JSON 塞进 `saw`**（存成 `{"saw":"...","say":"..."}` 这么一串），
    拿去发评论就变成一坨乱码 —— **真发出去过一次**。现在写存档前统一过 `normImpression()`，
    拼卡/拼评论时再过一遍 `asText()`：字符串是 JSON 就解开取内容，对象就按常见键名取第一个。
12. **评论发完别拿"评论列表里有没有"当判断** —— 列表按热度/分页给数据，新评论经常翻不到，
    容易误判成"没发出去"。正确姿势是**按 rpid 反查** `reply/reply?root=<rpid>`
    （实测几条全都 `root 存在=true`，正文一字不差）。刚发完索引还没跟上，要重试几次（现在是 4 次 ×2.5s）。
14. **"评论发出去了但别人看不见、@ 也没通知"** —— 不是发送失败，是**被 B站 压审核**。
    判据看 `state`：`0` = 公开，`17` = 没公开（只有发布者自己看得见）。
    实测同一账号同一天：长文 + @ + 一堆标点引号 → `state=17`；换成一句短评
    `@昵称 熊出没老粉看了会有共鸣` → `state=0` 直接公开。这就是为什么默认开**短评模式**。
    另外：**别用评论列表判断成败**（列表按热度/分页给数据），也别信"我自己看得见"——
    发布者能看到自己没公开的评论，所以只有 `state` 说了算。
15. **待审名单不能自己手改 `state.json`** —— 插件内存里那份会把外部的改动覆盖掉。
    要回填老评论用命令 `comment_track {bvid, rpid}`，它走正常的读-改-写。13. **`code 12051 重复评论，请勿刷屏`** 只在同一个视频上发第二条时出现
    —— 这本身就说明前一条已经登记进 B站 了。换一条视频即可，不是登录态的问题。

# 自主角色养成（persona-evolution）

让机器人**按自己的名字去研究对应角色的性格**，把研究结果和群聊里养成的记忆结合成一段
动态人格注入提示词，并**随着聊天缓慢演化** —— 不是一瞬间换人设，而是慢慢变得有性格。

例子：机器人叫「沙耶哦」→ 自动剥出「沙耶」→ 找到《沙耶之歌》的沙耶 → 提炼出
「说话轻而短、带疏离感」的性格卡 → 在这个群里一点点磨成属于这个群的说话方式。

---

## 它解决什么问题

原来的机器人只按固定的 `roleText` 人设说话，容易出现两个毛病：

1. **死板**：人设写了什么就照着念，换个群还是同一套腔调，没有"被群里的人磨过"的痕迹。
2. **没有来历**：人设里的性格是别人手写进去的，机器人自己不知道"我为什么是这样"。

这个技能补上这两点：性格**来自它自己的名字**（有来历），并且**会在每个群里分别演化**（会被磨）。

---

## 四个部分

| 文件 | 职责 |
|---|---|
| `character.js` | 名字 → 角色候选。剥掉昵称尾缀（「沙耶哦」→「沙耶」），判定歧义 |
| `profile.js` | 角色 → 性格卡；近期对话 → 小幅演化增量（调模型） |
| `store.js` | 持久化 + **有界演化**（两重夹取，杜绝瞬间换人设） |
| `inject.js` | 按会话渲染注入片段（同步、只读缓存） |
| `index.js` | 工具注册 + 生命周期钩子 + 装配 |

## 配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用自主角色养成 | 开 | 总开关。关掉后不再注入，已学的性格保留 |
| 角色出处 | 空 | 留空=按名字自动找。重名多时手动填 `角色名@作品名`，例如 `沙耶@沙耶之歌` |
| 性格力度等级 0-10 | 5 | 0=完全不注入；3=轻微口癖；5=性格明显仍是群友；8=主导说话方式；10=最大 |
| 每多少轮演化一次 | 40 | 累计到这么多轮真实对话才微调一次。**这是"慢慢变"的关键** |
| 单次演化幅度 1-3 | 1 | 每个维度单次最多挪多少 |
| 允许联网研究角色 | 开 | 关掉则只用模型已有知识 |
| 性格最大偏移 0-100 | 35 | 相对角色卡基准的最大偏离，防止长期跑飞 |
| 重置所有已学性格 | 关 | 一次性开关：打开保存后清空所有会话的性格演化（不动聊天记忆），重置完请关回去 |

### 力度等级的实际差别

以力度 5 和 9 为例，注入的段落长度差不多，但**口径不同**：

- 力度 5：`下面的性格倾向自然地融进你的说话方式即可，不要刻意表演`
- 力度 9：`下面的性格倾向请**明显体现**在语气和用词里，让它成为你这个群里最主要的说话方式`

力度 ≤3 时还会明确降级为"只是参考，不是必须照做的设定"。

## 五个工具

| 工具 | 用途 | 群里门控 |
|---|---|---|
| `status` | 查看当前角色、性格数值、演化进度 | 不门控（回答"你是什么性格"是正常对话） |
| `set_character` | 用户指定角色出处 | 需被 @ 或拍一拍 |
| `set_intensity` | 调整性格力度 | 需被 @ 或拍一拍 |
| `evolve_now` | 立刻微调一次（不等攒够轮数） | 需被 @ 或拍一拍 |
| `reset_persona` | 清空本会话养成的性格 | 需被 @ 或拍一拍 |

**为什么改配置的要门控**：工具不是钩子，模型在群里可以自己决定调用它们。
不门控的话，一句普通聊天就可能把角色设定改掉。

## 设计要点（都是踩过坑总结的）

### 1. 两层状态，既有底色又会被磨

- `characters[角色]` —— 角色卡，长期不变的**基准**
- `chats[会话]` —— 某个群**当前**的性格，从基准缓慢漂移

所以"我是谁"稳定，"我在这个群变成什么样"会变。

### 2. 有界演化：两重夹取

```
单次位移 ≤ evolveRate        （模型给 +100 也只走 1~3）
相对基准偏离 ≤ maxDrift       （连推 200 次也夹在基准 ±35）
```

实测：连推 200 次 +3 后停在基准 +35，一步都不越界。

### 3. 动态片段只追加在末尾

框架（`src/prompt.js`）有明确警告：动态片段插在系统提示中间会把后面所有规则的
字节位置推来推去，**系统提示的缓存前缀直接归零**。所以本技能只提供一个动态段，
由框架按 priority 排序**追加到末尾**。

### 4. 不重复注入聊天记忆

记忆由框架自己的 `memory.formatForPrompt` 注入。这里只负责"我是什么性格、
本群把我磨成了什么样" —— 记忆提供**发生过什么**，这里提供**因此我更倾向于怎么做**，
两者互补而不是重复。

### 5. 演化走 `after-response` 钩子，不阻塞回复

`promptSections(context)` 是**同步**的、每轮都会调用，在里面发 LLM 请求会卡住提示词组装。
所以：`before-context` 起后台解析角色，`after-response` 记账并在攒够轮数后
**后台**发起演化（不 await），失败也不影响这一轮回复。

### 6. 模型调用必须关掉思考模式

本机实测 `deepseek-flash` 在 thinking 模式下会把 `max_tokens` **全部**花在
`reasoning_content` 上，返回 `finish_reason=length` 且 `content=""` —— 正文一个字都没有。
所以 `llm.js` 默认发 `thinking: { type: 'disabled' }`（按各家方言给参数），
并在网关不认这个参数（400/422）时自动摘掉重发。

### 7. API Key 必须走 `resolveApiKey()`

不能直接读 `cfg.api.apiKey` —— 那是"手动模式"的遗留字段。用户在 UI 里选了
目录提供商之后，真正的 key 在 `cfg.dshProviderKeys[providerId]` 或
`providers[].apiKey` 里，此时 `api.apiKey` 是空的。

### 8. 内容安全是硬约束

角色可能来自成人向作品（例如《沙耶之歌》）。研究提示词里明确要求：

- 只提炼**性格气质与说话调性**，绝不提炼成人情节
- 必须写出 `forbid`，包含"涉及色情暴力内容""扮演恋人关系"这类禁令
- 注入段末尾固定带【底线】：角色只是语气来源，事实与安全规则永远优先

实测生成的卡片里 `forbid` 确实包含这些条目。

## 存储

`<data>/persona-evolution/state.json`

放 data 目录而不是技能目录：技能目录在 app 包里，升级会被覆盖；
temp 目录会被清理，而性格养成必须持久。读写用临时文件 + rename 保证原子性，
并留一份 `.bak`（损坏时自动回退）。

上限：角色卡 40 张、会话状态 120 个，超出按最近使用淘汰。

## 已知限制

1. **角色识别依赖模型的先验知识**。冷门角色可能找不到或找错；重名多时会发起确认。
2. **自动研究只在已配置模型时可用**。没有可用模型时技能仍会加载，注入部分照常工作，
   但研究/演化会明确报错。
3. **演化是否发生由模型判断**。实测模型偏保守（样本不足时给空增量），
   这是刻意的 —— 宁可不动，也不要凭几句话改性格。
4. **需要重启应用才能生效**。首次安装或改动本技能文件后，Electron 的 ESM 模块缓存
   不会在进程内刷新（热重载对"曾经加载失败过的模块"无效）。用
   `POST /api/skills/reload` 对**正常加载过**的模块有效。

## 博士等级
博士等级由已获得的声望决定。
声望，即博士经验值，在作战结束时发放，积累一定数量后可以提升博士等级。
一般地，作战通关时（剿灭作战则为行动结束时）按10倍实际消耗理智的比例（1:10）给予声望。

如果是三星或四星通关，声望获取提升至1.2倍（即变为1:12）。
剿灭作战的任何歼灭数均固定为1.0倍（1:10）。
不消耗理智的作战、使用演习功能进行的作战均不会产生声望奖励。
当声望积累到一定量即会升级，升级时会回复等同于新理智上限等量的 -45 -75的等量理智。不同的博士等级对应的理智上限及升级所需声望见下表。

自局部坏死（2019/12/24）版本起，声望等级上限由100提升至120。
自揭幕者们（2024「感谢庆典」）版本起，所有声望等级提升45理智上限。
升级时回复的理智量与此版本之前相等（即改为新等级理智上限-45）。
在此版本之前已注册登录的玩家在本版本上线后将立即获得45理智作为上限提升补偿。
自相变临界（七周年庆典）版本起，所有声望等级再提升30理智上限。
升级时回复的理智量不变（即改为新等级理智上限-75）。
在此版本之前已注册登录的玩家在本版本上线后将立即获得30理智作为上限提升补偿。
博士等级达到最高等级时，不再掉落声望。


## 干员信赖
信赖值是一种特殊的属性值，其生效原理由两部分组成：

信赖百分比：游戏中的外显“信赖值”，将会影响该干员的信赖加成属性及各类附属资料的解锁；
信赖点数：游戏内部决定信赖百分比的点数。
两者之间的对应关系如本节末尾列出的表格内容所示。


### 获取信赖
干员可通过完成关卡与进驻基建两种方式获取信赖点数，从而提升信赖值。

每次作战完成后，作战编队中的所有干员，每人获得等量的信赖点数，其数值等于下述算法得出的结果。

自未许之地版本（2025/12/5）起，作战完成后获得的信赖点数统一为实际消耗的理智数量，剿灭作战全权代理不获得信赖点数。
被安排到基建内的干员，在不同时间段可获得不同类型的信赖及其给定点数，其需要玩家手动收取。
进驻信赖（橙色）在干员进驻任意设施（活动室除外）时，每日4:00产生。信赖点数根据基建内所有宿舍的总氛围值计算，最高100/次。
副手信赖（蓝色）在干员被任命为基建副手时，每日4:00及16:00产生。信赖点数由其所在职位决定： 中枢副手的蓝色信赖根据基建内所有宿舍的总氛围值计算，最高500/次； 楼层副手的蓝色信赖根据其主管楼层内的单间宿舍的氛围值计算，最高125/次。
活动信赖（黄色）在干员被安排到活动室时，每日4:00及16:00产生。信赖点数根据其使用的活动室氛围值计算，最高125/次。
同一干员单次可获得多种信赖（如进驻任意非活动室的基建副手），但无法单次获得多个同种信赖。手动收取顺序为副手信赖→活动信赖→进驻信赖，未收取的信赖会在其对应的获取时间直接被新的同种信赖替换。


### 信赖的计算
随着干员信赖点数的增加，干员的信赖值也会逐渐提高，每个干员也会获得各自不同的信赖属性加成。同时，信赖值还会影响该干员的资料、语音、干员密录和模组等的解锁。

干员信赖值达到100%后，属性加成达到上限。
计算助战干员的属性加成时，要先将其信赖值除以2再向下取整，以此计算对应的信赖属性加成。也即只有提供200%信赖值的干员，该干员才能以100%信赖加成的状态供好友使用，反之同理。
需要注意的是，若因助战干员处于精英阶段0或队伍中没有精英化干员使得助战干员被限制至精英阶段0时，助战干员的最终信赖加成将存在50%信赖值的上限。
自未许之地版本（2025/12/5）起，助战信赖加成限制全部取消。助战干员的信赖值与其在持有者的状态完全同步。
当一个干员拥有异格时，该干员和其异格的信赖值共享；同时参与行动/进驻基建时将会各自独立计算产生的信赖值。

## 属性
### 定义
游戏战斗内的所有实体单位都拥有属性，其在计算过程中的典型状态如下：

原始属性：指单位某个属性的数据值，一般指由数据文件直接定义的属性的基本数值，可理解为刨除任何加成和修饰后的最原始数值。
而在通常情况下，信赖、潜能和模组提供数值也会在这一步计（算）入，使得原始属性变为原始属性+参与后续运算。该计入除特殊情况外后续不再特别说明。
基础属性：原始属性在进入战斗后，经过符文运算、取上下限后获得的数值。
部分机制实现的判断标准以此数据为准，如卫戍协议：盟约中【阿戈尔】盟约的数值获取、信仰搅拌机的保底攻速、百炼嘉维尔生息演算模组的加成上限。※部分官方文本中“基础属性”的指代不明或意义不明，因此不在此处的讨论范围内。如鼓舞术语: 鼓舞获得额外附加的基础属性加成（同类属性取最高）※鼓舞提供的属性加成算法为最终加算（非基础属性加成）※同类效果取倍率最高（非最终数值）生效中的“基础属性”含义不明（可能是早期实现方案的遗留问题），而偷取术语: 偷取减少目标的基础属性作为自身加成，目标减少和自身加成的属性不超过指定上限（同类属性取最高）※目标/自身的属性变化均使用最终加算（非基础属性）※若未指定上限，则双方属性增减益无上限；指定上限时，每个目标均可被偷取最多上限值的减益量※目标受到来自多个来源的偷取属性减益时，每个受影响属性取各自的最高偷取减益值生效※本质上为独立的目标属性减少与自身属性增加的两个效果，与目标是否具有相应数值的属性无关中的“基础属性”无任何实际指代对象与处理（其实现方式亦与基础属性无关）。
（实际）属性：基础属性经过属性计算器完整处理后获得的数值。
对于绝大部分情况下，这就是最终呈现给玩家的数值，绝大部分机制以此为判断标准。
属性上限/属性下限：由属性类型定义的属性上下限，个体的属性上下限可被部分游戏机制更改；默认的上下限可在数值范围页面中查阅。


### = 修饰器 =
在获得原始属性值后，决定属性最终数值前，往往会从Buff等地方收集属性修饰器（AttributeModifier）。
属性修饰器分四种：直接加算（ADDTION）、直接乘算（MULTIPLIER）、最终加算（FINAL_ADDITION）、最终乘算（FINAL_SCALER），有关修饰器运算的详细信息请见#属性基本公式。
修饰器的种类决定了其在属性计算时参与到“哪个位置”，同时也决定了一部分特殊的效果是否能单独享受该修饰器。


### = 从源实体获得基本属性 =
从源实体获得基本属性（fetchBaseValueFromSourceEntity）是一种特殊的修饰器模式。使用该模式时，对应的属性修饰器将被重写。

目前有且仅有辅助分支“吟游者”（如空，浊心斯卡蒂）使用此模式，其鼓舞效果中会将原为最终乘算的修饰器重写为最终加算的修饰器。


### = 符文运算 =
符文计算通常通过符文来导入，从而实现在“局外”对角色类单位原始属性、敌人类单位原始属性的修改。
※因为一些历史遗留问题，站内关卡页符文相关描述中的“敌方单位”实际应为“敌人类单位”，“我方单位”实际应为“角色类单位”。
符文属性运算会直接作用于单位的原始属性上，此处以 \( \alpha \) 指代运算前数值。
符文属性运算过程中有加算与乘算两种计算方法，并且加算的优先级通常高于乘算，具体运算方法如下：

当多种同计算方式数值叠加时，叠加结果为：
符文加算结果\(R_p = p_1 + p_2 + \cdots + p_n\)
符文乘算结果\(R_t = t_1 t_2 \cdots t_n\)
所以符文属性运算的最终结果为：
新的原始属性：\(A = R_t(\alpha + R_p) \)


### = 特殊：藏品符文 =
在集成战略（及类似的玩法）中，对于收藏品及能力提升系统提供的加成有一套特殊且相对独立的符文运算体系，可称之为“藏品符文”。

相对的，对于上述提到的符文加算和乘算，因为其常通过关卡定义的符文提供，这里称之为“关卡符文”。
通常情况下，藏品符文和关卡符文一样，也有加算与乘算两种计算方法，还有类似于最终乘算的后置乘法，不过其会进行同类叠加：

藏品符文加算结果 \(C_p = cp_1 + cp_2 + \cdots + cp_n\)
藏品符文乘算结果 \(C_t = 1 + ct_1 + ct_2 + \cdots + ct_n\)
也就是所，藏品符文乘算是倍率叠加而不是叠乘。
藏品符文后置乘算结果 \(C_s = 1 * cs_1 * cs_2 * \cdots * cs_n\)
与最终乘算类似的，藏品符文后置乘算的每一项在为负数时都会被+1变为倍率值。
藏品符文本身是一个特殊的符文，通常后于上述的其他符文运算处理：

新的原始属性： \( A_+ = (A + C_p) * C_t * C_s \)


### 属性基本公式
修饰器共有四种类型，即属性变化有四种计算方式：
直接加算：直接对基础数值进行加算。
直接乘算：对直接加算完成后的结果进行乘算。
最终加算：对直接加算和直接乘算完成后的结果进行加算。在当前版本游戏内被描述为“获得额外附加的基础属性加成”（即鼓舞术语: 鼓舞获得额外附加的基础属性加成（同类属性取最高）※鼓舞提供的属性加成算法为最终加算（非基础属性加成）※同类效果取倍率最高（非最终数值）生效）。
最终乘算：对其余三种计算方式完成后的结果进行乘算。
修饰器叠加：除最终乘算为变化数值之间相乘外，其余均为相加。因此，修饰器叠加结果的计算公式为：
直接加算结果\(D_p = p_1 + p_2 + \cdots + p_n\)
直接乘算结果\(D_t = t_1 + t_2 + \cdots + t_n\)
最终加算结果\(F_p = p_1 + p_2 + \cdots + p_n\)
最终乘算结果\(F_t = t_1 t_2 \cdots t_n\)存在修正：当组成结果的任意一项小于0时，自动将其补正为原数值+1。
最终属性（实际属性）结果\(A_f = F_t[(A + D_p)(1 + D_t) + F_p]\)其中，若\(1 + D_t < 0\)，则\( (1 + D_t) \)自动补正为0。之后经过游戏数据基础#数值范围限制下限/上限，得到属性的最终结果。

### 移速
通常情况下，敌人在可以正常移动的每帧都会以寻路算法向着目标点以最短路径移动 \(\text{移动速度} \times m \div \text{帧率}\) 格直至其途径目标点，哪怕其与目标点之间的距离小于该数值也会移动（并越过那个位置），且移动时并不会检测本次移动的落点是否处于可通行地块。其中 \(m\) 为 move_multiplier。

move_multiplier 默认值为0.5，即通常情况下实际移动速度是一半（在二倍速下才会视觉相等）。
由于数值范围问题，移动速度数值不会低于速度下限0.1（即在 move_multiplier 为正常的0.5的情况下，每秒只能移动0.05格），但无上限。
虽然无法移动，但我方干员、装置、召唤物移动速度均为默认的1.0。


### 阻挡半径
大部分角色类单位阻挡半径分两个：地面阻挡半径、飞行阻挡半径
判断阻挡距离时会使用相应的阻挡半径平方数判断距离。

地面阻挡半径 = 0.70709997
地面阻挡半径平方数 = 0.49999037
飞行阻挡半径 = \(0.8944 \times \text{阻挡半径倍率}\)
飞行阻挡半径平方数 = \(0.79995137 \times \text{阻挡半径倍率}^2\)
装置（如障碍物）会覆写阻挡半径平方数，此时不论是地面阻挡还是飞行阻挡的判断都使用该数据。
巨型装置的阻挡半径平方数固定为0.49999037。


### 闪避公式
一个单位拥有多个闪避效果且不拥有其他类型的伤判效果时，最终的闪避成功率可视为叠乘。
即，闪避期望成功率 \(P = 100\%-[1-(1-P_a)(1-P_b) \cdots (1-P_n)] \)


### 维持技能状态
部分技能开启后，单位将不会执行普攻，而是进入一个持续执行技能效果的恒定状态，此状态即为“维持技能状态”，如星熊三技能“力之锯”、伊芙利特三技能“灼地”等。

### = 区别 =
区别于一般技能，“维持技能状态”存在如下特性：

免疫各类攻击速度减速及加速效果（如寒冷术语: 寒冷攻击速度下降30，如果在持续时间内再次受到寒冷效果则会变为冻结※直接加算※游戏中存在两类寒冷（互相之间不干预）：敌方寒冷与友方寒冷。两者主要区别为叠加成冻结的方式不同：※对已具有敌方寒冷或敌方冻结的敌人施加的敌方寒冷会变为敌方冻结※友方寒冷始终需要两两一对产生友方冻结，持续时间取双方之中最高※具有冻结免疫的单位身上的任何寒冷都不会尝试变为冻结※站内没有明确注明的情况下干员与我方召唤物施加的均为友方寒冷，敌人施加的均为敌方寒冷、活性地板的攻击速度BUFF等）；
眩晕、冻结等硬性控制会提前结束“维持技能状态”，进入技力恢复时间。


## 仇恨
2.7.01版本中，角色类单位的仇恨计算、进阶选择器、排序逻辑均出现了较大变动，当前页面仅供参考。
游戏中的各类“索敌”机制往往都依赖于仇恨这一系统，而仇恨排序、筛选的过程分为两个部分：权重计算和规则排序。而权重计算又分为“仇恨值计算”与“仇恨过滤器（postFilter）规则计算”两步。


### 仇恨值
每个单位的仇恨值都会根据自身的实体类型选用不同的计算式：

敌人类可以在地图上游走的单位，包括一般的敌人、中立的平民、自走车等，包括附着类敌人目标的仇恨值 = \(10^8 \times \text{嘲讽等级} - \operatorname{clamp}(\text{路径距离},-1 \times 10^8,10^8)\)
若所在地块可到达目标路径点，则路径距离为：终点距离（以所在地块的坐标为起点，直接串联所有路径点的到终点曼哈顿寻路距离之和，“传送门”之间的距离除外）+修正值（先取“自身所在具体坐标→当前地块中心”的向量V，然后取前进方向上这个向量V的投影值（可负））。单位为“格”，
若所在地块不可到达目标路径点，或自身处于地图外，则路径距离为：当前坐标至当前目标路径点的直线距离。单位为“格”，
通俗易懂的来讲，这一仇恨值计算方式可以理解为“自身离终点/路径点越近，仇恨值越高”。
随着2026年8月1日2.7.61版本更新，敌方单位公式中的嘲讽仇恨被翻了10000倍（已计入公式），并为路径距离添加了与1级嘲讽相当的上下限，现在持有嘲讽的敌人的仇恨会大于路径上存在坑洞的单位了。
角色类可以在地图上以格为最小单位部署的单位，包括一般的我方单位、召唤物、装置等，一部分看似敌人的也属于角色类单位目标的仇恨值 = \(3 \times 10^{8} \times \text{嘲讽等级} + \operatorname{clamp}(\text{创建时间} \times 1000 + \text{同帧内已部署单位数},-3 \times 10^{8},3 \times 10^{8})\)
创建时间的机制见章节#创建时间；同帧内已部署单位数每帧更新，用于区分暂停部署时单位的仇恨值。
在早期，由于角色类的仇恨值在无嘲讽的情况下取决于其创建时间，而公式中创建时间部分具有上限，因此可以认为10000s（≈2.78h）之后部署的所有角色类单位是“同时部署”的，在相同嘲讽等级情况下拥有相同的仇恨值。
随着2026年2月10日2.7.01版本更新，角色类的仇恨公式不仅引入了#同帧部署数，还将整体放大了1000倍这意味着在这之后，即使存在嘲讽等级2的敌人类单位，其仇恨值也只不过等同于或低于战斗开始2秒后部署的干员（已计入公式），已不再出现角色类同仇恨值的情况。
随着2026年8月1日2.7.61版本更新，干员的嘲讽等级又被独立翻了30000倍（已计入公式），导致持有嘲讽的干员的数值发生了溢出，出现+1嘲讽的情况下干员的仇恨机制将变得几乎无法正常处理。
随着2026年9月4日2.7.71版本更新后，干员的嘲讽等级收敛为了原先的1/1000（已计入公式），并且不再单独对创建时间进行上下限处理，现在的逻辑更接近不允许非嘲讽部分的仇恨超过-1~1嘲讽这一区间。
通俗易懂的来讲，这一仇恨值计算方式可以理解为“时间、顺序上越晚部署/出现，仇恨值越高”。
仇恨值的类型为定点数变量。
敌人类的仇恨值在计算途中为浮点数，在计算完成后才转译为的定点数。


### 创建时间
创建时间为每个单位创建时（例如干员部署、敌人出现），从“战斗开始”算起取得的当前战斗计时，上下限为[0,10000]，单位为秒由于游戏内时间处理相关的机制几乎无法精确到比帧更短的时间，因此可以简单将其理解为战斗计时每游戏帧更新一次（+0.033）。每个单位一经取值后通常该数值将不再变化。
部分仇恨过滤器不使用仇恨值而是直接使用创建时间计算参考值。
在月行水上版本2.7.71前，创建时间不再具有上下限（意味着不再存在“10000秒后所有单位都视为在同一时间部署”的情况）


### 同帧部署数
在辞岁行版本2.7.01后，不论自动部署、手动部署、自动放置，只要场上增加一个角色类单位，场上的“此帧部署数”+1（该数值默认为0，且会在下一帧部署单位的处理前归零），所有角色类单位单位出场时都会取用此时的“此帧部署数”作为自己的“同帧部署数”数据。这一逻辑意味着在相同的一帧内，每部署一个单位，接下来同帧部署的所有单位的仇恨值都会多1点。
不过这一逻辑导致玩家同一帧内部署超过33个单位时，这一帧的单位可能会超越下一帧部署的单位的仇恨值


### 仇恨过滤器
仇恨过滤器（postFilter）即为最常说的“索敌逻辑”，每次索敌往往都需要框定所有可选索敌目标单位，列成一份列表（默认为实体创建顺序），对列表进行一次过滤器排序；仇恨过滤器可能会对仇恨值进行二次计算，可能根据仇恨值（或根据其他数值）对目标列表进行排序、筛选、甚至打乱。
下面提到的“参考值（权重）”是为每个候选者标注的32bit浮点变量，越低在排序时越靠前，越靠前越容易被选为目标；自凯尔希开始，明日方舟引入了双权排序（即靠两个参考值配合排序的逻辑），因此部分过滤器中的候选者拥有两个参考值，通常情况下，双权排序只看第一参考值来排序，两个目标的第一参考值相同情况下才采用第二参考值处理先后顺序。
双权排序比起之前使用不同数据乘大数计算而言，它不容易出现数值“跃迁”的情况，以#阻挡数降序举例，即使一个单位的仇恨值高达1亿，只要有其他单位阻挡数比其更高，过滤器就仍会将那个阻挡数更高的单位排在列表前面。
若无特殊说明，仇恨过滤器使用到参考值进行排序时，将根据列表中每个单位的参考值（或第一参考值与第二参考值），对索敌列表进行稳定性排序（逻辑类似插入排序法），最后列表中最靠前(即参考值最小)的一个或数个单位将会被此次仇恨过滤器筛出，成为此次“索敌”的目标。
因为排序算法具有稳定性，并不会改变同值项的顺序，所以在情况下目标之间的顺序将会保持为默认的实体创建顺序，故这一情况下，索敌者将无关乎具体数值，优先选择更早创建（通常是部署）的单位。
这些仇恨过滤器的比对精度默认为0.001；不过最常见的4号过滤器（仇恨降序）以及76号过滤器（与自身间寻路距离升序）的比对精度为0.1。
在比较两个参考值时相当于会默认省略小数点后第3位（或第1位）之后的小数，因此参考值较为接近的情况下可能会因此被过滤器视为参考值相同曾经“游戏开始后每个3帧内部署的干员视为同帧部署”的原理便是放在角色类单位身上，每过去整整0.1s参考值才多+0.1，两个单位必须再不同的3帧区间才能出现“后部署先被打”的效果。
比对精度的原理为在比较时让双方的参考值（或第一参考值与第二参考值）乘以比对精度的倒数，后转为整型类（Int）再加以比对。由于辞岁行后角色类单位的嘲讽等级1级便有10000000，乘以倒数的1000后极易达到整型类的21亿的数值上限/-21亿的数值下限，可能导致计算出错。
由于仇恨过滤器之间的差距过大，此处会将它们分章节而非列表格进行介绍。
如需查看各种仇恨过滤器的详细信息，请前往仇恨页面页面进行查阅。

## 弹道
弹道，又称抛射物，在明日方舟中可以是一根弩箭、一发导弹、乃至锁链、飞向敌人的鸟、爆炸aoe、三个环绕飞行的小球，全部都是弹道。
一些弹道拥有碰撞体积，依靠碰撞实现效果；一些弹道具有自己的目标，在时间或距离达标时产生效果。弹道携带着许多完成一次攻击所需的信息，毕竟它本身就是一种攻击方式（远程攻击）的核心。

判断一个攻击是否为弹道的粗略方法是看实体发射这个弹道时，攻击伤害和特效等是不是即时的，如果需要一段时间则它即为弹道。
部分攻击（例如能天使的普通攻击）虽然看似有弹道，但实际不具有弹道。其攻击与伤害之间的“子弹”仅为特效，并非弹道效果。


### 移动行为
弹道的移动行为决定了它“视觉上是如何运动”的，尽管实际游戏中的复杂情况可能导致其偏离自己所产生的视觉效果（例如直线移动的弹道可能因为敌人的高速移动而看起来像曲线运动等）。

※注意，视觉效果通常与实际移动方式无关


### 转向速度
部分弹道存在转向机制，其转向速度表示速度（向量）向目标方向变化的权重，其格式为 \(\frac{A}{B}\)。
其中 \(B\) 为总权重，\(A\) 为目标方向的权重占比，\(B-A\) 为本帧速度方向的权重占比。
令 \(\vec d\) 为本帧速度方向，\(\vec t\) 为目标方向。对于每个下一帧，在转向速度影响下，弹道方向将变化为：
\(\vec d'=\vec d\cdot\frac{B-A}{B}+\vec t\cdot\frac{A}{B}\)
举例：在平面直角坐标系上，弹道位于 \((0,0)\)，敌人位于 \((10,10)\)，弹道速度始终为 \(10\)，本帧弹道方向为 \((1,0)\)，转向速度为 \(\frac{1}{5}\)，目标方向为 \((0.7071,0.7071)\)，则下帧方向为：
\(\vec d'=\frac{4}{5}(1,0)+\frac{1}{5}(0.7071,0.7071)=(0.94142,0.14142)\)
下帧速度为 \((9.4142,1.4142)\)。


### 最大存在时间
大部分有目标的弹道具有被称为“最大存在时间”的参数，该参数将决定弹道从出现开始，最多能存在多长时间。弹道达到其存在时间上限后将自动消失。

注意 大部分弹道在存在时间归零时，若弹道仍未击中其目标，则弹道立刻视为击中了目标（可配置）。
注意 目前存在大量抛射物具有3秒、5秒、10秒的存在时长（可配置）；部分技能与其创建的弹道绑定，若出现弹道因各种原因无法消失，相关技能可能因此将要持续维持到弹道自动消失为止。
受变速效果影响时，最大存在时间也会同比例变化（存疑）。


### 可变速模式
逻各斯的3技能延异视阈的效果中提及了"使攻击范围内敌方子弹的飞行速度大幅降低"（以下简称为视阈），该机制将受弹道的可变速模式影响。

若弹道的移动类型为可变，则（待补充）
若弹道的移动类型为不可变时，始终不可变速（NO）。
弹道有3种可变速模式：自动识别（AUTOMATIC），可变速（YES）, 不可变速（NO）

可变速模式为AUTOMATIC时，若弹道包含一个可见的视觉特效，则可被视阈减速；否则不可被视阈减速；
可变速模式为YES/NO时，可/不可被视阈减速。


### 可消除模式
逻各斯的3技能延异视阈的效果中还提及了"将其（攻击范围内敌方子弹）全部清除"（以下简称为视阈），该机制将受弹道的可消除模式影响。
弹道有3种可消除模式：自动识别（AUTOMATIC），可消除（YES）, 不可消除（NO）

可消除模式为AUTOMATIC时，可被视阈消除与否与可变速模式的结果保持一致（可减速即可消除，不可减速即不可消除）；
可消除模式为YES/NO时，可/不可被视阈消除
非自动识别模式下，可变速模式与可消除模式没有直接关系，因此可能存在可以被减速但无法被消除的弹道，也可能存在可以被消除但无法被减速的弹道。


## 异常效果
### 异常效果（AbnormalFlag）
持有异常效果（AbnormalFlag）的单位会受到此异常效果相关联的效果。

异常效果的本质是一个开关型二进制数据，通过 Buff 和状态机控制开关状态和持续时间，其本质可理解为一个效果黑箱和指示灯。参见章节“#异常效果标记（AbnormalFlagMask）”。
注意：异常效果（AbnormalFlag）不是 Buff，不存在持续时间或叠加，许多游戏内产生的效果实际是 Buff 和异常效果的共同作用，站内所有使用获得数秒某异常效果的描述实际意义为获得一个或数个携带这个异常效果的 Buff。
部分异常效果隶属于“无法选择”效果，可以干扰来自不同阵营/相同阵营/治疗行为的对象选取（见下方#无法选择）。


### 异常组合（AbnormalCombo）
异常组合（AbnormalCombo）为包括了一个或多个的异常效果（AbnormalFlag）的组合。
持有该组合即视为同时拥有这些异常效果（AbnormalFlag），但不会受到针对于单一异常效果免疫或无视的影响。


### 异常免疫（AbnormalImmune）/异常组合免疫（AbnormalComboImmune）
持有异常免疫（AbnormalImmune）时，该异常免疫对应的异常效果（AbnormalFlag）无法生效，无法被检测（但不会清除携带该异常效果的Buff，异常免疫结束时该Buff的异常效果可重新起效）。持有异常组合免疫（AbnormalComboImmune）时，该异常组合免疫对应的异常组合（AbnormalCombo）将不会再提供对应异常效果，无法被检测。
敌人与干员的配置中有数个以布尔型变量形式存在的便捷配置可以快速未单位提供对应异常免疫/异常组合免疫。该类配置被开启且被设置为TRUE时，该干员与敌人将在初始化时会获得对应的异常免疫（AbnormalImmune）或异常组合免疫（AbnormalComboImmune），通常我们称这些称为“异常抗性”。

除此之外，部分异常效果免疫具有不局限于其对应异常效果的效果：


### = 反隐（隐匿免疫） =
持有隐匿免疫（又称反隐效果）的单位，身上的迷彩效果会失效。不过其与迷彩免疫不同，无法真正阻止其他机制对迷彩的检测，因此同时具有隐匿免疫与迷彩的单位会被部分非索敌能力认为“具有可正常生效的迷彩”。部分单位即使不具有隐匿，在受到隐匿免疫效果影响的瞬间也会产生特殊的机制交互（如土遁忍者)。


### = 浮空抗性（浮空免疫） =
持有浮空免疫会禁止一切含有异常效果浮空的Buff施加，尝试施加浮空的逻辑也可能会相应失效（与浮空异常反制的表现类似）。


### = 缚地抗性（缚地免疫） =
持有缚地免疫会禁止一切含有异常效果缚地的Buff施加，尝试施加缚地的逻辑也可能会相应失效（与缚地异常反制的表现类似）。


### = 传送抗性（被传送免疫） =
传送免疫的实现方式之一。被传送异常效果本身不具备任何机制和效果，仅有被传送免疫有实际用途。


### 异常反制（AbnormalAnti）
获得包含异常反制（AbnormalAnti）效果的 Buff 时，包含了对应异常效果（AbnormalFlag）的 Buff 会被立刻清除。
异常反制生效期间，包含对应异常效果（AbnormalFlag）的 Buff 无法被添加。
※区别于异常免疫（AbnormalImmune），异常反制会清除掉包含对应异常效果的 Buff，且阻止此类 Buff 被添加；而异常免疫通常只会令对应的异常效果暂时无法生效。


### 异常效果标记（AbnormalFlagMask）
使用标志枚举的方法将该 Buff 的所有异常效果合并为一个值，其中的每个位标志相当于 1 << abnormalFlag的ID。
例如，一个同时附带STUNNED（晕眩）和TARGET_FREE（不可选中）的 Buff，其异常效果标记（AbnormalFlagMask）等于 1 << 0 | 1 << 2，即5。


### 异常效果的统一检查
由于机制上的需要，明日方舟对许多异常效果的检查进行了统一检查，站内也会相应的进行标注。以下是站内标注的一些有关异常效果分类“词汇”的实际含义：


### = 无法选择 =
“无法(被敌方)选择类异常效果”指的是在处理单位“能否(被对立的阵营)选择？”（get_targetFree）方法时检查的五个异常效果：
隐匿、不可选中、无敌、塔不可选中、对地规避（索敌者行动方式不为地面的情况下忽略）
如果单位持有上述五个异常效果之中的任意一个，常见的、来自不同阵营的“选择”行为将无视这些单位进行（如同范围内不存在这个单位）。
若单位目前处于部署保护通常来说角色类单位被部署后，通常直至部署状态机结束前会处于部署保护状态，直至被系统视为“部署完成（Located）”为止。部署保护期间，单位无法被敌对阵营单位选中（类似于异常效果不可选中）。不出意外的情况下，通常单位的部署保护持续直至部署动画播放完毕的那一帧。期间、或处于DISAPPEAR状态机下，自动视为无法选择（即使其不具备上述异常效果中的任何一个）。
※虽然迷彩也能在特定情况下避免选择，但其应用于单位的选择器上，不属于无法选择类效果，仅进行该检查时不会处理。
※部分选取能力可以通过无视某一特定异常效果的方式来“无效化”此类干扰效果从而选取到目标；直接选中的能力不会进行具体的目标选择，故同样不受这些仅在选择时生效的异常效果制约。
※与之类似的还有“无法被友方选择”与“无法被治疗选择”，值得注意的是选择器必须启用enableAdvancedOptions才会检测的无法选择类异常效果、禁疗和孤立，站内所提及的“无视可选性”通常指的就是未开启该配置。


### = 无法被友方选择 =
“无法被友方选择类异常效果”指的是在处理单位“能否被相同阵营选择？”（get_allyTargetFree）方法时检查的异常效果，即孤立（ALLY_TARGET_FREE）
由于原名相同且具有唯一指代性，对其用例，站内通常直接标注对应的异常效果（如“不受孤立制约“、“无视孤立”）。


### = 无法被治疗选择 =
“无法被治疗选择类异常效果”指的是在处理单位“能否被治疗行为选择？”（get_healFree）方法时检查的异常效果，即孤立（HEAL_FREE）
由于原名相同且具有唯一指代性，对其用例，站内通常直接标注对应的异常效果（如“不受禁疗制约“、“索敌效果无视禁疗”）。
即使一个单位的治疗行为可以无视“无法被治疗选择类异常效果”选择目标，也不代表其治疗可以应用在目标身上，相应的治疗效果施加在单位身上时也可能因禁疗而无效。


### = 阻止攻击 =
“阻止攻击类异常效果”指的是在处理单位“能否攻击或阻挡攻击？”（get_canUseAtkOrCbt）方法时检查的八个异常效果：
晕眩、无法行动、浮空、冻结、麻痹震颤、缴械（持有无敌情况下忽略）、强制缴械、小睡
如果单位持有上述八个异常效果之中的任意一个，则该单位被视为“无法攻击或阻挡攻击”，基于该检定的相关机制或能力将无法生效。
值得注意的是，失衡（UNBALANCE）不属于异常效果，它是一种状态机，故失衡也不属于阻止攻击类异常效果，哪怕其实际防止了单位发动攻击。此外，战栗虽然能在实质上阻止敌方单位在阻挡状态下发动攻击，但不属于上述八者，因此不会影响此检查。举例来说，使用该检查来造成伤害水遁忍者，在失衡状态机下或阻挡且持有战栗的情况下仍然能正常造成伤害。


### = 阻止能力 =
“阻止能力类异常效果”指的是在处理单位“能否使用能力？”（get_canUseAbility）方法时检查的六个异常效果：
晕眩、无法行动、浮空、冻结、麻痹震颤、小睡
如果单位持有上述六个异常效果之中的任意一个，则该单位被视为“无法使用能力”，不过许多能力可以绕过这一限制，固其阻止能力的称呼并不完全准确。


### = 阻止移动 =
“阻止移动类异常效果”指的是在处理单位“能否移动？”（get_canMove）方法时检查的四个异常效果：
束缚、自缚、冻结、浮空
实际上晕眩、无法行动、麻痹震颤同样因切换状态机而让单位无法移动，但不属于此类效果，哪怕其实际防止了单位进行主动移动。


### = 对友方隐藏 =
“对友方隐藏类异常效果”指的是当一个能力未绑定选择器时，其作为“默认触发逻辑”处理友方单位“是否隐藏？”（get_isHiddenToAlly）方法时检查的三个异常效果：
隐藏、小睡、无敌
此判定对绑定了选择器的能力无效。


### = 对非友方隐藏 =
“对敌方隐藏类异常效果”指的是当一个能力未绑定选择器时，其作为“默认触发逻辑”处理非友方单位“是否隐藏？”（get_isHidden）方法时检查的两个异常效果：
隐藏、无敌
此判定对绑定了选择器的能力无效。


### 可影响沉睡单位的伤害
部分干员的伤害可以“无视沉睡”，其逻辑本质上是让自己的伤害具有8号SharedFlag（即DAMAGE_CAN_HURT_SLEEPING_ENTITY）。
单位在处理目标无敌异常效果所带来的“无法受到伤害与元素损伤效果”时，会先判定“假定目标具有沉睡免疫的情况下，是否仍具有无敌/隐匿/不可选中/塔不可选中之一”。

若通过，视为“即使无视沉睡也无法造成伤害”，因而不论是否具有该SharedFlag伤害都会被归零
若未通过，则可因上述SharedFlag而“无视无敌”造成伤害。
该判定存在下述关联情况：

目标处于出场/部署/消失状态机中会自动通过这一判定。
因为小睡不是沉睡，无视沉睡的伤害也无法影响小睡单位。

心情消耗/时

根据进驻贸易站的干员数量可获得基础心情消耗加成：进驻2人为-0.05，进驻3人为-0.1，进驻1人时无加成。
进驻贸易站的干员可通过后勤技能对贸易站产生一定数值的心情消耗加成，在控制中枢进驻的每一名干员也会为贸易站提供-0.05的心情消耗加成。
此处计量表只计入对贸易站内全体干员生效的心情消耗加成，因此实际干员心情消耗可能存在差异。
\(\text{进驻贸易站干员的实际每小时心情消耗} = 1 + \text{贸易站基础心情消耗加成} + \text{后勤技能与中枢产生的贸易站心情消耗加成} + \text{对当前干员生效的后勤技能心情消耗加成}\)

\(\text{贸易站实际获取订单效率} = 1 + \text{基础获取订单效率加成} + \text{后勤技能产生的获取订单效率加成}\)

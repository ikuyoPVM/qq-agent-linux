# 明日方舟大师（arknights-master）

让 QQ Agent 在群里聊到《明日方舟》时，像一个真正懂行的群友那样回答：干员资料、术语黑话、
养成机制、玩法规则、资源凭证、关卡与活动，并且**不编数值** —— 拿不准的一律查资料。

- 类型：**LLM 型技能**（`skills/`），靠"注册工具 + 提示词片段"生效，用不用由模型判断
- 触发：**默认「被 @ 或戳一戳才启用」**——不被叫到时，4 个工具在模型眼里根本不存在、
  大师提示词也不注入（不打扰闲聊，也不占提示词）。私聊直接放行（1v1 没有 @ 机制）
- 数据来源：**PRTS Wiki**（<https://prts.wiki>，「玩家共同构筑的明日方舟中文 Wiki」）

## 触发时机（默认：被 @ 才启用）

"被 @ 才启用"不是靠提示词里写一句话（模型可能忽略），而是**两道确定性闸门**：

| 闸门 | 机制 | 效果 |
|---|---|---|
| 工具闸门 | `providers['tool.guard']` | 本轮没被叫到 → 直接否决这 4 个工具，模型连工具定义都看不到 |
| 提示词闸门 | `promptSections(ctx)` | 本轮没被叫到 → 不注入"方舟大师"那段提示词，顺带省 token |

两者共用同一个判断（`lib/trigger-gate.js`），依据是每轮开始时 `before-context` 钩子记下的：

- **被叫到**：`@机器人`（以 @ 段的 QQ 号为准，重名不误判）、**拍一拍**、**引用回复机器人**、**私聊**
- **聊到方舟**：正文命中方舟术语或内置图鉴里的干员名（用于"聊到明日方舟时"模式）
- **宽限窗口**：被 @ 后的 N 分钟（默认 3）内，同一个群的追问仍然放行——不用每句都 @

设置项「什么时候启用」有三档：`被@或戳一戳时`（默认）／`聊到明日方舟时`／`总是`。
宽限时间设成 `0` 就是严格模式：每条消息都必须 @ 才启用。

> 想看闸门到底有没有生效：控制台的**会话详情**里有"本次排除了哪些工具"，
> 被闸门挡掉时会写明确原因，例如「明日方舟大师：本轮没有被 @ 或戳一戳」。

## 它有什么

**① 内置离线资料库**（`kb/`，秒回、不联网、不花 token 在网络上）

| 文件 | 内容 |
|---|---|
| `kb/operators.json` | 全量干员图鉴：职业、分支、稀有度、位置、标签、特性、所属、情报编号、外文名、画师、配音 |
| `kb/operators-list.md` | 干员一览表（按职业分组），回答"有哪些六星先锋"这类问题 |
| `kb/recruit.json` | 公开招募池：可公招干员 + 星级 + 公招标签（公招计算器的数据） |
| `kb/wiki/*.md` | PRTS 核心页面正文逐字抄录：术语、职业、技能、技能专精、模组、信赖、基建、公开招募、理智、源石、合成玉、龙门币、资质/采购/寻访凭证、博士、剿灭作战、危机合约、集成战略、生息演算、保全派驻、剧情、首页 |

**② 六个工具**（模型按需调用，工具 id 会自动加前缀 `arknights-master__`）

| 工具 | 作用 |
|---|---|
| `operator_info` | 干员资料卡；`detail=true` 时联网补技能/天赋/模组/满级属性/获取方式 |
| `kb_search` | 离线检索内置资料库（机制、术语、玩法、资源） |
| `recruit_calc` | **公开招募（公招）标签计算**：算能出的干员范围、保底/最高星级，并推荐最优组合（保底 4★ 等） |
| `bilibili_search` | **搜 B 站视频**：搜出候选 → 逐个取播放量与投币数 → 按「播放 + 投币」综合排序，**只给一条最优的**；返回标题、UP 主、播放、投币、时长、链接 |
| `prts_search` | 联网检索 prts.wiki 页面（找页面名用） |
| `prts_page` | 联网读取指定页面正文（关卡、活动、材料、剧情、敌方单位……） |

## 群里的数字梗（325 / 799）

被 @ 或戳一戳的那一轮里，消息中只要出现这两个数字，机器人就会把你在设置里填的整段文案
**一个字不改**地发出来：

| 触发 | 默认发什么 | 在哪填 |
|---|---|---|
| 消息里出现 **325** | 一段「长难句」：把 325 的来历（魔法ZC目录 仙术杯第五届 第三层关底利刃所指暴毙、结算 325 分）一口气说完的反问句 | 设置 → 技能 → 明日方舟大师 → **「325」要发的内容** |
| 消息里出现 **799** | **《打灰燃曲》（血狼战歌）歌词**（11 行，emoji 与换行都原样发出） | 同上 → **「799」要发的内容** |

> 两段都是**逐字原样发出**：不改字、不翻译、不加解释、不拆句。想换成别的直接改这两个设置框（留空 = 该梗不回应）。

几个要点：

- **打字和发表情都算**：QQ 表情在消息里就是 `[表情325]`，所以机器人看到的文本里天然带这个数字。
- **只在被叫到时回**（和你选的开关一致）：没 @ 机器人、也没在宽限时间里，就不会插话。
- **留空 = 这个梗不回应**，两个可以单独开。
- 长数字里的 325/799（比如 `13259`）**不会**误触发。
- 机制上是「检测命中 → 在本轮消息末尾追加一条『必须原样发出这段』的指令」，
  所以它不占常驻提示词，也不会打乱你和其他技能的关系。

**③ 一段提示词片段**（`skill.json` 的 `prompt.sections`，priority 45）
告诉模型：什么时候切进方舟模式、哪些内容必须先查证、术语按官方口径、群里回答要短。

## 设置项（设置 → 技能 → 明日方舟大师）

| 设置 | 默认 | 说明 |
|---|---|---|
| 什么时候启用 | 被@或戳一戳时 | 另可选「聊到明日方舟时」「总是」 |
| 被叫到后的宽限时间（分钟） | 3 | 被 @ 后这段时间内，同群追问仍算叫过你；0 = 严格每条都要 @ |
| 允许联网查 PRTS Wiki / B 站 | 开 | 关掉后只能用内置资料库：更快更省，但新干员/新活动查不到、B 站搜索停用（公招计算仍可离线用） |
| 单次返回正文上限（字符） | 3000 | 联网读页面时回给模型多少字，500~12000 |
| PRTS 默认检索条数 | 5 | `prts_search` 默认返回几条 |
| B 站候选池大小 | 8 | B 站只发一条，但会取这么多候选来比播放/投币，1~10 |
| 群里的数字梗（325 / 799） | 开 | 关掉后这两个梗都不接 |
| 「325」要发的内容 | 空 | 出现 325 时原样发出的文案（长难句）；留空 = 不回应 |
| 「799」要发的内容 | 空 | 出现 799 时原样发出的文案（血狼战歌）；留空 = 不回应 |
| 资料里附 PRTS 链接 | 开 | 工具返回值里带上来源链接，方便群友自己看 |

## 更新内置资料库

内置数据是**某一天的快照**。想更新时，重新抓一遍 PRTS 即可：

1. 干员图鉴：抓 `Category:干员` 全部页面 → 逐个取页面 wikitext 的 `{{CharinfoV2}}` 字段
   （API 示例：`https://prts.wiki/api.php?action=query&prop=revisions&rvprop=content&rvslots=main&rvsection=1&format=json&formatversion=2&titles=夜刀|玫兰莎`，一次最多 50 个标题）
2. 机制页面：`https://prts.wiki/api.php?action=query&prop=extracts&explaintext=1&redirects=1&format=json&titles=术语|职业|…`
   把 `query.pages[].extract` 原文写进 `kb/wiki/<页面名>.md`（首行 `# 页面名`，第二行 `> 来源：<链接>`）
3. 干员一览表由 `kb/operators.json` 重新生成
4. 公招池（`kb/recruit.json`）：抓 `https://prts.wiki/api.php?action=parse&page=公开招募&prop=text&format=json&formatversion=2`
   渲染后的 HTML，从词条表里抽出「干员名 + 星级 + 公招标签」，写成
   `{"source":"…","fetchedAt":"YYYY-MM-DD","tagPool":[...],"items":[{"name":"…","stars":3,"tags":["近战位","输出"]}]}`
   （星级能从 `kb/operators.json` 按名字补；`支援机械` 应当只对应 1★、`资深干员` 只对应 5★、`高级资深干员` 只对应 6★ —— 可以用这三条自检抓得对不对）

> 抓不到的动作可以让 AI 帮你做：把上面两段 API 说明丢给 AI 即可。
>
> ⚠️ **热重载的边界**：QQ Agent 的热重载只重新加载入口 `index.js`，
> **`lib/` 下的子模块会被 Node 的 ESM 缓存住** —— 改了 `lib/` 里的文件、或给它加了新导出，
> 要**重启一次 QQ Agent** 才生效（只改 `index.js` / `skill.json` / `kb/` 是即时的）。
> 遇到"改了没反应"时先想这条，不要怀疑语法。

## 目录结构

```
skills/arknights-master/
├── skill.json          清单（设置项、web_fetch 权限声明）
├── index.js            入口：setup(api) 注册 6 个工具 + 提示词片段 + 触发闸门
├── lib/trigger-gate.js "被 @ 才启用"的闸门（before-context 钩子 / tool.guard / promptSections）
├── lib/prts.js         prts.wiki 访问层（超时、缓存、wikitext 解析）
├── lib/local-kb.js     内置资料库的索引与检索
├── lib/recruit.js      公招计算（标签对齐、命中集合、组合推荐）
├── lib/bilibili.js     B 站搜索原语（搜索接口 + 风控降级）
├── lib/bili-ranking.js 「挑一条最优」的策略层（详情补投币数 + 播放/投币综合评分）
├── lib/memes.js        群里的数字梗（325/799 检测与原样注入）
├── kb/                 内置数据（operators.json / operators-list.md / recruit.json / wiki/*.md）
└── README.md           本文件（加载器不读它，删掉也能跑）
```
